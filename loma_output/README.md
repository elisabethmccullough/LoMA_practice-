# HTT LoMA local haplotype reconstruction foundation test

This folder records the setup/run attempt for local assembly of the synthetic HTT-region evidence package over `chr4:3074400-3075400`.

## Correct LoMA package/tool

The relevant tool is **LoMA** from `kolikem/loma` (Localized Merging and Assembly): <https://github.com/kolikem/loma>. It is a localized long-read assembly tool designed to build consensus sequences from reads in a target region and, when structural-variant evidence permits, classify reads into diploid haplotypes for haplotype-resolved consensus generation.

The upstream README identifies release `v1.1.3` as the release to download, and documents dependencies on:

- Python `>=3.8`
- `minimap2 >=2.0`
- `MAFFT >=7`
- Python libraries `numpy` and `matplotlib`

## Correct input format

LoMA does **not** take a single FASTQ path directly. It expects:

- `-I`: an **absolute path** to an input directory containing one or more `*.fastq` files
- `-O`: an **absolute path** to an output directory

For this HTT test, the combined-read command should be equivalent to:

```bash
scripts/run_htt_loma.sh /workspace/LoMA_practice-/loma_output
```

Internally, the script prepares:

```bash
/workspace/LoMA_practice-/loma_output/inputs/local_reads/HTT.local_reads_from_bam.fastq
```

and then runs LoMA as:

```bash
bash <path-to-loma>/loma \
  -I /workspace/LoMA_practice-/loma_output/inputs/local_reads \
  -O /workspace/LoMA_practice-/loma_output/local_reads
```

Optional haplotype-split FASTQs are prepared and run similarly when present:

- `HTT.hap1.reads.fastq` -> `loma_output/inputs/hap1_reads/`
- `HTT.hap2.reads.fastq` -> `loma_output/inputs/hap2_reads/`
